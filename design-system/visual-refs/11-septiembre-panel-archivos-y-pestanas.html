5Lo que hay que mirar

Del análisis crítico del plan. Nada de esto es bloqueante, pero los tres se cobran si se ignoran.

  • El riesgo real es el merge, no el runtime. Cuatro archivos de upstream reciben injertos. Son props opcionales y pocas líneas, pero cada uno es un punto de conflicto futuro: si un git merge upstream/main los toca, revisar primero WorkspaceMain.tsx.
  • Tres columnas no entran abajo de ~1400 px. A 1920 px sobra espacio (272 + chat + 292 + 320). Más abajo el chat queda asfixiado. El plan no agrega auto-colapso por ancho; queda como sugerencia.
  • Varias pestañas = varios WebSockets con el mismo token. Es el objetivo del pedido y no está probado en este fork: notificaciones duplicadas y doble conteo en el medidor de 5 h son los síntomas a vigilar.
  • El service worker cachea el bundle. Recargar normal no alcanza: Ctrl+Shift+R o parece que el cambio no se aplicó. Ya pasó en este repo.
  • El auto-refresco depende del WebSocket. Si una sesión queda colgada en “procesando”, el flanco nunca llega. No es regresión —hoy no hay refresco de ningún tipo— pero el botón manual es la red.
